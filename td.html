Temporal difference: judge each step, not each episode.

Monte Carlo has to wait for the end of an episode, and it cannot tell good moves from bad ones inside it. The fix is the single most important idea in reinforcement learning: estimate every value relative to the next one. It gives us SARSA, Expected SARSA and Q-learning.

01The idea of temporal difference

Monte Carlo estimates the return in an absolute way: add up all the rewards to the end. Temporal difference (TD) states each estimate relative to the estimate of the next step, with just one reward in between: "my value is the reward I get now, plus the value of where I am next". The terminal state, worth 0, is the anchor that holds the chain in place.

Temporal difference

Neither is simply better. Monte Carlo uses the true outcome but must wait; TD learns at once but leans on estimates that may still be wrong (this is called bootstrapping). With long or never-ending episodes, waiting is the bigger problem.

02The maths and the TD error

The return satisfies \(G_t = R_{t+1} + \gamma G_{t+1}\), so our averaged estimates should satisfy the same relation. We move each estimate a step towards the TD target:

\[ \begin{aligned} V(S_t) &\leftarrow V(S_t) + \alpha\,\big[\underbrace{R_{t+1} + \gamma V(S_{t+1})}_{\text{TD target}} - V(S_t)\big] \\[4pt] \delta_t &= R_{t+1} + \gamma V(S_{t+1}) - V(S_t) \qquad \text{(the TD error)} \end{aligned} \]

The difference \(\delta\), the TD error, compares two predictions of the same thing made one step apart. Its sign is what matters, and it comes back in every later part: positive means better than expected, negative worse, zero means nothing to learn.

Example: driving home

A classic from Sutton & Barto (Example 6.1). Each evening you predict your total travel time at several points. Monte Carlo waits until you are home (43 min) and moves every prediction towards 43. TD moves each prediction towards the next prediction, at once: the rain gets the blame for the rain, the truck for the truck.

03Three choices for the next action

For action values the target needs "the value of the next step". The next state is given by the environment. For the next action there are three choices, and they give three algorithms:

\[ Q(S,A) \leftarrow Q(S,A) + \alpha\,\big[\,\text{target} - Q(S,A)\,\big] \] \[ \begin{aligned} \text{SARSA:}&\quad \text{target} = R + \gamma\, Q(S',A') \\ \text{Expected SARSA:}&\quad \text{target} = R + \gamma \textstyle\sum_{a'} \pi(a'\mid S')\, Q(S',a') \\ \text{Q-learning:}&\quad \text{target} = R + \gamma \max_{a'} Q(S',a') \end{aligned} \]

One experience, three updates

The agent is in (2,3) and takes right: R = −1, lands in (3,3). Edit the row of (3,3).

SARSA asks "how good was it, given what I actually did next?" Expected SARSA averages over what the policy might do. Q-learning assumes the best. With the same experience, one TD error can be positive and another negative.

04On-policy and off-policy: the cliff

SARSA and Expected SARSA learn the value of the policy they are actually following, exploration included: on-policy. Q-learning's target uses the best action, whatever the agent does, so it learns about the optimal policy directly: off-policy. The cliff (Sutton & Barto, Example 6.6) makes the difference visible: −1 per step, −100 and back to the start for stepping off the cliff, ε = 0.1 throughout.

05Sample efficiency: the race

Sample efficiency is how many episodes (or steps) a method needs to become good. All four methods run with the same ε schedule (0.9 → 0.1), γ = 0.8 and α = 0.1, averaged over many runs.

Monte Carlo, SARSA, Expected SARSA, Q-learning

Pick a maze. The big one needs 22 moves; episodes stop at 60 steps.

On the small maze TD is a bit faster. On the big maze the difference is total: a random walk almost never reaches the cheese within 60 steps, so Monte Carlo has nothing to learn from. TD learns from every step: squares the agent keeps returning to become worse than squares it rarely visits, which pushes it outwards until it finds the cheese.

06Q-learning, one step at a time

Q-learning (Watkins, 1989) is probably the most famous algorithm in RL. Watch one episode, update by update: look at the next square's row, take the maximum, multiply by γ, add the reward, and move the old entry 10% of the way towards that target.

Inside the Q-table

The table after some training. Yellow frame: the entry being updated.

Why the max? Bellman's principle of optimality: if a whole sequence of decisions is optimal, every decision after the first must be optimal too (full marks in an exam means full marks in every section). So the value of acting optimally now is the reward now plus the value of acting optimally from the next state:

\[ q_*(s,a) = \mathbb{E}\big[\,R_{t+1} + \gamma \max_{a'} q_*(S_{t+1}, a') \;\big|\; S_t = s,\ A_t = a\,\big] \]

Q-learning is this equation turned into an update, with one sample in place of the expectation.

07Eligibility traces: credit further back

One-step TD passes news back one square per visit. An eligibility trace is a fading memory of recently visited squares: each visit adds 1, and every step all traces shrink by \(\gamma\lambda\). When a TD error arrives, every square is updated in proportion to its trace. λ = 0 gives back one-step TD.

08For comparison: with a world model

Everything so far was model-free. If the agent knows where every action leads, it does not need to try anything: it can apply the Bellman optimality equation to every square again and again. This is value iteration. Edit the maze by clicking squares.
