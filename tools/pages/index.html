Learning by trial and error.

In supervised learning we gave the computer the answers. In unsupervised learning we gave it data without answers. In reinforcement learning we give it neither. It has to act, see what happens, and receive a single number telling it how well it did. From that alone, it must work out what to do.

01How would you teach a robot to tie a shoe?

A computer does exactly what it is told. That is perfect for adding two large numbers, and hopeless for tying a shoe, folding a T-shirt or walking: nobody can write down how every joint should move and what every force will be. So we do what we do with a child or a dog. We let it try, and we tell it afterwards how well it went. Good outcomes make the behaviour more likely; bad ones make it less likely.

02Agent and environment

Every RL problem has an agent and an environment. The agent is whatever you can control directly; the environment is everything you cannot control directly but are trying to influence through the agent. The agent sends actions; the environment sends back states. Both must be numbers.

Where is the boundary?

Learning to drive, starting from zero. The same person, three different agents.

Choose the framing

The boundary, and even the size of one action, is a choice. Closing your fist: one action, or five, one per finger? Choose the framing that gives the problem the clearest structure.

Key idea: the agent only chooses actions and receives states and rewards. Everything it cannot control is the environment.

03The loop: state, action, reward

One more signal completes the picture: the reward, a single number after every action. Positive is good, negative is bad. It evaluates what was done; it never says what should have been done instead. The result is a sequence in discrete time steps:

\[ S_0,\ A_0,\ R_1,\quad S_1,\ A_1,\ R_2,\quad S_2,\ A_2,\ R_3,\ \dots \]

This is a Markov decision process (MDP). If it ends, at the target or after a time limit, the sequence is called an episode. Below, you are the agent in the small maze used throughout this site: −1 for every step, 0 for entering the goal square, at most 25 steps.

Notation

The reward that follows action \(A_t\) is written \(R_{t+1}\): it arrives together with the next state. Some sources, including the video this course follows, write \(r_t\). Nothing changes except the index.

Key idea: learning happens inside this loop: act, observe the new state and the reward, adjust, repeat.

04The Markov property

Ideally, the next state depends only on the current state and action, not on anything earlier. Then the state contains enough information to predict what comes next. The agent does not need to know the physics; the information just has to be there.

A robot that catches a ball

Move through time. Where will the ball be one step later?

The same reason explains why the pendulum of Part 6 has four numbers in its state, not two. The MDP is not perfect: real situations are not always Markov, it uses one fixed time step, and squeezes all feedback into a single number. It is still the best framework we have, and nearly all of RL is built on it.

Key idea: if the current state contains everything that matters, the agent can forget the past.

05The strategy: a policy

The agent's strategy is the policy \(\pi(a \mid s)\): the probability of choosing action \(a\) in state \(s\). Think of it as a function from states to actions, with some randomness allowed. Why randomness? A learner that always does the same thing can never discover that something else would have been better.

06The total reward: the return

The agent wants a large total reward, not just a large next reward: what pays most now can cost you later. The return adds up all future rewards, each multiplied by one more factor of the discount factor \(\gamma\) between 0 and 1:

\[ G_t = R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \dots \qquad\Longrightarrow\qquad G_t = R_{t+1} + \gamma\, G_{t+1} \]

The second form is the one we use again and again: the return now is the next reward plus γ times the return one step later. It also means returns are easiest to compute backwards, from the end.
